Motion findings: as built and the options

Real desktop screens in frames. Each card is one option; the green outline is the one I recommend. Buttons play the moment. Nothing in the system has changed.

1. Three loops that never stop

WCAG 2.2.2 Pause, Stop, Hide (A): motion that starts by itself, runs over 5s beside other content, must be stoppable on the page, unless it is essential (a loading indicator is). The system "reduce motion" setting does not count. Measured: assistant rings, one turn per 24s; the light round Talk to AI, 3.2s; the drone mark sways 3.6s. All endless.

As built

Fails 2.2.2: endless, no stop

Rings turn, light circles the button, the mark sways, propellers spin, all the time.

A · Remove all three

Passes

Everything stands still. The desktop is quieter.

B · Move only while the assistant answers

Passes: a status indicator

At rest all still. While it composes an answer the rings and the propellers turn: then the motion means "working".

C · Keep all, add a pause control

Passes, formally

Everything moves as now; a control on the page stops it. A control added only to stop motion that says nothing.

2. The job offer's 10 seconds

HIG · Progress indicators: when the duration is known, show determinate progress. WCAG 2.2.1: a real-time offer is an allowed exception. WCAG 1.4.1: the seconds stay in words too. Both options pass.

As built

Passes

"Expires in 8s" in words, standing still.

Countdown: words + a bar that empties

Passes

The figure counts 10 → 0 and a thin charcoal bar empties with it (green stays only on Accept). Into the backlog as a component; not built now.
