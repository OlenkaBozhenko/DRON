Input fields — what should go, and what cannot

First, the finding that changes the question. The input already has no border — your own snapshot reads border: 0px none, and there is no rule in the kit that draws one. What reads as обводка is the row panel: the warm card the group of fields sits inside. So the real question is whether that panel stays, and the three options below answer it.

Both of these are HIG. iOS has two form styles: the grouped inset list (Settings — a card, rows, separators, value on the right), which is what is built; and the plain field (Notes, a search bar — no box, just the caret and a grey placeholder), which is what you described. Neither is more correct than the other; they are for different screens.

A · as built — the grouped panel

HIG's grouped inset list. The card says "these rows are one group", the hairline separates them, and the field itself draws nothing.

And the grey placeholder — how light can it go

A placeholder is text, so WCAG 1.4.3 asks it for 4.5:1 like any other string. That puts a hard floor under "ледь сірим", and the floor is closer than it looks: today's placeholder is already only one small step above it.

The lightest that still passes — #6C6963, 4.52:1

This is the end of the road, not a middle option: one shade lighter and the placeholder fails AA. Whether it even reads as lighter than today is worth judging with your own eyes.
