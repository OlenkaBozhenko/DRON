3 Common Market Patterns

  • P-1 Live tracking is the baseline, not a feature. Every delivery product in the set shows real-time status. Users trained by Bolt and Glovo expect to see order location at every moment. No tracking = no trust. Source: screenshots + wing.com/technology + Devlight NP case.
  • P-2 Maximum 3-step ordering flow across all mature products. Wing: shop → pick location → receive. Glovo: order → track → get. Zipline: pick → watch → get. Any product exceeding 3 primary steps loses mobile conversion. Source: wing.com, zipline.com WebFetch.
  • P-3 Numbers, not adjectives, build credibility. Wing (1M+ deliveries, 12 years), Zipline (60K lives saved, 70M miles), DroneDeploy (3M sites, 180 countries), Flytrex (200K deliveries, FAA-certified). "Trusted" and "reliable" appear nowhere in hero copy. Source: WebFetch from each homepage.

3 Key Differences

  • D-1 Trust anchor is origin-dependent — no universal model. UA players (Nova Poshta) use physical presence. Global tech (Wing, Zipline) use technology lineage. Drone platforms (Flytrex) use regulatory cert. DRON must build cold-start trust from zero — operator verification + insurance is the only available mechanism.
  • D-2 B2B vs B2C is a hard architectural split. DroneUA and DroneDeploy are purely B2B. Glovo and NP app are purely B2C. DRON's two-user-type model (client + operator SRM) has no direct reference in this set.
  • D-3 Every peer hides the operator. DRON won't — this is the differentiator. In Glovo, NP, Wing, and Flytrex the operator is invisible. DRON shows a named, photo-verified human operator. Closest reference: Bolt (driver card pre-arrival). Unfamiliar in the drone category — both a risk and a structural advantage.

Top 3 Mechanisms for DRON MVP

M-01 · Bolt pattern
Operator visible immediately after payment
Post-payment screen shows operator name, photo, rating, and "Certified by DRON / Insured" badge before the operator has moved. Converts the highest-anxiety moment — right after money leaves — from unknown to known.

Apply in DRON: "Order confirmed" screen = operator card + live map + ETA. Never a generic "order received."
Bolt/Uber · benchmark score 31/35 · general UX knowledge
M-02 · Airbnb pattern
Trust signals on the list card — no extra tap
Airbnb's +25% booking increase came from surfacing Superhost/Verified badges at browse stage, visible on the card before any tap. If trust info requires an extra tap, most users won't look.

Apply in DRON: Operator card must show without tapping — photo · rating · Verified badge · Insured badge · jobs count.
Source: Raw Studio — Airbnb +25% case study
M-03 · Zocdoc pattern
Credential-first profile structure
Zocdoc leads every doctor profile with license, board certs, and NPI before bio or photos. Professional standing — not personality — is the primary trust signal for a first-time user.

Apply in DRON: Profile opens with — "Certified operator · CAA/EASA license · Insured 500 000 UAH · 47 jobs." Bio comes after.
Source: Usability Geek — Zocdoc UX case study
Will NOT work
Rover — "Message first → meet & greet → then book"

Rover requires messaging a sitter, waiting for a reply (frequently ignored), arranging a pre-booking meeting, then booking. Appropriate for multi-day pet care. Fatal for DRON.

DRON's audience arrives with a Bolt/Glovo mental model: sub-60-second booking. Any async negotiation before confirmation makes the perceived value equal to Kabanchik.ua. Rover itself documented this failure: "sitters frequently ignore messages without consequence, leaving owners feeling ghosted." — Kinship.com

Section 03

UX Patterns

5 fundamentally different interaction patterns for speed-first on-demand services. Evaluated against DRON's context from CLAUDE.md.

01 Auto-Dispatch — system decides Selected for DRON

Client specifies service type + location → system assigns nearest certified operator → booking confirmed. No selection step, only confirmation.

Used in
Bolt, Uber, Glovo (courier), Amazon Flex, emergency dispatch
Fits when
Operators are interchangeable · Speed is primary · Platform guarantees quality via standards
Breaks when
Operators are differentiated · Service needs pre-start coordination · Client doesn't trust the platform
Why it fits DRON
1. Company owns all operators — any = guaranteed quality
2. Speed is the core product value
3. Audience has no criteria to evaluate drone pilots — auto-dispatch removes the question
02 Marketplace Browse — client selects from a list Secondary · Photo/Inspection only

Client sees list/grid of available operators with profiles → browses → selects → confirms. Decision is entirely the client's.

Used in
Airbnb, TaskRabbit, Rover, Upwork, Fiverr
Breaks when
Speed is critical → choice paralysis · First time, no evaluation criteria (Whalen: Decision mind)
03 Broadcast / Race to Accept Not suitable for DRON

Client posts job → system broadcasts to multiple operators → first to confirm gets it. DRON has employed operators — broadcast has no architectural basis. Core failure: recreates the Kabanchik.ua anxiety this product replaces.

04 Calendar-First / Slot Booking Condition X: planned services

Client selects date + time → system shows available operators for that slot → confirm. Time is the primary axis.

Used in
Zocdoc, Treatwell, Calendly, barbershop apps
When to use in DRON
Aerial photography + inspection: weather-dependent, daylight-sensitive, client presence required. MVP: Delivery → auto-dispatch / Photo+Inspection → calendar-first.
05 Guided Wizard / Progressive Disclosure Not applicable — repeat use

System narrows options via sequential questions. Useful for first-time onboarding only. Breaks for repeat users who can't skip steps. Mobile context + multiple screens = drop-off by screen 3.

Chosen Architecture: Two-mode flow

MVP interaction model

Auto-Dispatch + Calendar-First depending on service type

Delivery
Service → Location → Confirm → Operator assigned → Pay → Track

2 taps to confirmed booking. System decides. No selection step.

Photo / Inspection
Service → Details → Pick slot → Confirm → Operator assigned → Pay

Calendar-first. Client controls timing. Operator auto-assigned to slot.

Hypotheses — if / then / because [source]

H-01
If DRON shows operator photo + rating + "Verified by DRON" badge on the order confirmation screen (post-payment, not pre-selection),
then first-order cancellation rate will decrease,
because Bolt's model of immediate operator identity disclosure converts the highest-anxiety post-payment moment from unknown to known. — benchmarks.md M-1
H-02
If DRON uses auto-dispatch for delivery and calendar-first for photo/inspection (two modes, one product),
then booking completion rates will be higher than a single unified flow,
because delivery users are in urgency mode while photo/inspection users are in planning mode — one flow optimizes for neither. — ux-patterns.md, CLAUDE.md
H-03
If Verified + Insured badges and job count are visible on the operator card in the list — without a tap into the profile —
then operator selection drop-off will decrease,
because Airbnb's +25% booking lift was driven by surfacing these signals at browse stage, before commitment. — Raw Studio
H-04
If first-time clients receive a 15-second in-app explainer before their first booking ("here's what happens after you confirm"),
then activation drop-off at the operator selection screen will decrease,
because Whalen's Emotion mind identifies "stranger with a drone near my property" as the highest unresolved anxiety in activation, and CJM marks operator selection as the #1 drop-off point. — user-stories-cjm.md, Whalen 6 Minds
H-05
If operator payment is auto-released within 30 min of client confirmation (or auto-confirmed after 2 hours),
then operator retention will improve,
because the primary operator churn risk is building direct client relationships to bypass the platform — payment friction is the fastest trigger for that exit. — CJM Operator Stage 4
H-06
If DRON launches without a "Book again" one-tap shortcut for returning clients,
then repeat order rate will underperform,
because Memory (Whalen) overload during re-booking is the #4 critical drop-off point in the CJM, and users trained by Bolt/Glovo expect zero re-entry effort. — CJM Drop-off #4
H-07
If operators are required to upload a result photo before the job can be marked complete,
then client satisfaction on first use will be higher,
because users trained by Nova Poshta app (5M+ active users in UA) expect proactive visual evidence of completion, not just a status string. — Devlight NP case study

UX · Customer Journey

Customer Journey Maps

4 stages: Attraction → Activation → Involvement → Retention. Drop-off risk rated 🔴 high / 🟡 medium / 🟢 low. Friction mapped to Whalen's 6 Minds.

Whalen's 6 Minds — reference

Vision
What users see and attend to — hierarchy, contrast, scanning
Critical CTA invisible; wrong visual hierarchy
Wayfinding
Navigation and spatial orientation within a system
User lost in multi-step flow; can't go back
Memory
Working memory limits — 7±2 chunks max
Too many fields/steps at once → overload
Language
Word processing and terminology comprehension
Drone jargon ("UAV", "payload") alienates users
Decision
Choice under uncertainty; expert vs novice differences
Too many operators to compare → paralysis
Emotion
Fear, trust, anxiety, delight — the deepest mind
"Stranger with drone near my home" → abandonment

Source: John Whalen, Design for How People Think (O'Reilly, 2019) · uxr.cl review
